    Wie ich arbeite

    Das einzig bekannte Gegenmittel gegen schlechtes Design ist Leidenschaft, gepaart mit Erfahrung und den richtigen Workflows. Daraus sind ein paar Grundsätze geworden:

    Eine Quelle für Design und Code.
    Tokens und Komponenten in Figma sind mit den echten Code-Komponenten verknüpft. Gebaut wird mit echten Werten, nicht mit nachgemessenen Pixeln.
    Erst die Regeln, dann die KI.
    Agenten bauen so gut wie ihre Vorgaben. Wer ihnen Tokens und Komponentenregeln mitgibt, bekommt brauchbaren Code zurück.
    Konsistenz hält länger als Effekte.
    Ein Design System soll einen Auftritt über Jahre tragen, nicht nur bis zum Launch.
    Direkt, ohne Zwischenebene.
    Abgestimmt wird mit dem, der gestaltet. Das spart Umwege und eine Menge Meetings.
    Diskretion gehört dazu.
    Die meisten Projekte laufen über Agenturen, deshalb nenne ich Kundennamen nur auf Nachfrage.
    Kleine Werkzeuge, die eine Sache gut machen.
    Was im Alltag fehlt, baue ich selbst: ohne Netzwerk, ohne Telemetrie, offen im Code.
    Privatsphäre ist der Normalfall.
    Diese Seite setzt keine Cookies, misst niemanden und lädt nichts von fremden Servern nach.

    UI/UX Design mit Figma

    Problem: Meetings über das Design dauern länger als das Design selbst.

    Interfaces und Experience Design für Websites, Web-Apps und digitale Produkte. Entworfen und abgestimmt wird in Figma, FigJam und Dev Mode, damit alle am selben Stand arbeiten.

    Figma FigJam Dev Mode

    Passt, wenn

    • ein Relaunch oder Neubau ansteht.
    • eine Agentur Verstärkung im UI/UX braucht, remote und ohne Einarbeitungsvorlauf.

    Figma-to-Code Workflows

    Problem: „Figma-to-Code“ heißt oft: Copy-Paste und debuggen bis Mitternacht. Und Figma-Files mit 99+ Seiten, aber keiner weiß, wo das finale Design liegt.

    Design und Code teilen sich eine Quelle: Tokens und Komponenten in Figma sind über Dev Mode und Code Connect mit den echten Code-Komponenten verknüpft. Statt Pixel nachzumessen, übernimmt die Entwicklung verbindliche Werte, und jede Komponente folgt einem festen Vertrag. Screenshot und Hoffnung haben ausgedient.

    Dev Mode Code Connect Design Tokens

    Passt, wenn

    • ein Figma-File da ist, aber der Weg in den Code jedes Mal Tage kostet.

    Design Systems & Tokens

    Problem: Design Tokens existieren, aber niemand nutzt sie konsistent.

    Aufbau und Pflege von Token-Sets, Komponenten-Bibliotheken und Styleguides, damit ein Markenauftritt über Jahre konsistent bleibt. Die Tokens liegen maschinenlesbar vor, so arbeiten Menschen und Werkzeuge mit denselben Werten.

    Figma Variables Design Tokens Komponenten Styleguides

    Passt, wenn

    • ein Design System entstehen soll oder zerfallen ist und Ordnung braucht.

    Im Code

    Agentic Coding & AI

    Problem: KI generiert Code schneller, als du „Figma Dev Mode“ sagen kannst. Und die KI entscheidet jetzt selbst, was sie baut.

    KI-Agenten schreiben Code weitgehend selbstständig. Damit dabei kein Wildwuchs entsteht, brauchen sie Design-Vorgaben in maschinenlesbarer Form: Tokens, Komponentenregeln, klare Struktur. Genau diese Vorarbeit ist Teil der Leistung, ebenso die Pipelines, in denen Design zu Code wird. Damit die KI baut, was du meinst.
